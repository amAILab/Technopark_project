# План подготовки демо панели Технопарка ко вторнику

Дата обновления: 2026-05-09.

## Цель

Показать проректору не «сайт», а рабочий инструмент управления проектным портфелем Технопарка: где есть движение, где нужны решения, что готово к НТС и грантам.

## Безопасный маршрут до показа

### 1. Стабилизировать данные

- Использовать текущую Google Sheet как основной источник.
- Держать локальные XLSX/CSV и `data/fallback-dashboard.json` как резерв.
- Не менять названия листов, `gid` и ключевые колонки перед демо.

### 2. Проверить публичную копию

- Открыть: `https://amailab.github.io/Technopark_project/`.
- Если кэш мешает: `https://amailab.github.io/Technopark_project/?v=demo-tuesday`.
- Проверить 5 блоков: KPI, решения руководителя, план на 7 дней, гранты, повестка НТС.

### 3. Подготовить сценарий показа

- Использовать `docs/PRORECTOR_SHOWCASE_SCRIPT.md`.
- Время: 3–5 минут.
- Главный акцент: панель помогает назначать ответственных и принимать решения.

### 4. Fallback на случай сбоя

Если Google Sheets/App Script не ответит:

1. Открыть сайт с параметром `?v=demo-fallback`.
2. Показать, что панель использует локальный `fallback-dashboard.json`.
3. Сказать: «Данные синхронизируются с таблицей, но для показа есть автономная копия, поэтому демонстрация не зависит от внешнего сбоя».

## Что не делать до демо

- Не чистить массово JS/CSS.
- Не менять структуру таблицы.
- Не переносить проект на новый хостинг.
- Не добавлять новые сущности, если они не помогают показу проректору.

## Мини-чек перед показом

- [ ] Сайт открывается на GitHub Pages.
- [ ] Данные не нулевые.
- [ ] Работает режим/блок для НТС.
- [ ] Есть понятный список «что требуется от руководителя».
- [ ] Есть fallback-сценарий.
- [ ] Открыты README и отчёт качества данных на случай вопроса про источник данных.

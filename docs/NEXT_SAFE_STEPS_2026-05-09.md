# Технопарк РГСУ — безопасные следующие шаги

Дата: 2026-05-09.

Цель: улучшать демонстрационную готовность без риска сломать работающую витрину до ближайшего показа.

## Что уже можно делать безопасно

1. Проверять синтаксис JS-файлов через `node --check`.
2. Обновлять документацию демо: сценарий показа, fallback-фразы, список рисков.
3. Дополнять чек-листы для владельцев данных без изменения структуры Google Sheets.
4. Фиксировать вопросы к Никите/команде отдельным списком, не в коде.

## Что не трогать без отдельного решения

- Структуру таблиц и названия колонок.
- Apps Script URL и обработчик формы НТС.
- Логику загрузки данных и fallback-путь.
- Массовую чистку JS/CSS-файлов: сейчас это риск выше пользы.

## Мини-бэклог до показа

| Приоритет | Задача | Риск | Комментарий |
|---:|---|---|---|
| 1 | Пройти демо-сценарий на 3–5 минут | Низкий | Только ручная проверка интерфейса |
| 2 | Подготовить короткую речь руководителя | Низкий | Без изменений в коде |
| 3 | Проверить отправку формы НТС в тестовом режиме | Средний | Только если Никита подтвердит внешнее действие |
| 4 | Согласовать владельцев данных по проектам/грантам | Низкий | Организационный шаг |
| 5 | После показа разобрать дубли JS/CSS | Средний | Лучше отдельной веткой/коммитом |

## Вопросы к Никите

- Для кого ближайший показ: руководство, команда технопарка, НТС или внешний партнёр?
- Нужна ли версия «только для руководителя» без технических деталей?
- Какие 3 проекта/гранта обязательно должны выглядеть сильнее остальных?

# Панель руководителя Технопарка РГСУ

Компактная управленческая панель для Проектного центра «Технопарк РГСУ».  
Сайт помогает руководителю, членам НТС и проектной команде быстро видеть состояние проектного портфеля, риски, готовность к грантам, повестку НТС и ближайшие управленческие действия.

Проект работает как статический сайт на GitHub Pages и получает данные из Google Sheets и Apps Script. Структуру Google Таблицы сайт не меняет.

---

## 1. Основная задача панели

Панель должна отвечать на 5 управленческих вопросов:

1. Сколько проектов сейчас в портфеле.
2. Какие проекты требуют решения руководителя.
3. Что нужно сделать за ближайшие 7 дней.
4. Какие проекты готовы к грантам.
5. Что нужно вынести на заседание НТС.

Главный принцип: сайт не должен быть витриной. Это рабочая панель управления проектами.

## 4. Ключевые поля Google Sheets

Панель особенно зависит от следующих полей:

| Поле | Зачем нужно | Что будет, если пусто |
|---|---|---|
| Проект / название | Идентификация проекта | Проект будет отображаться неясно |
| Ответственный | Назначение владельца проекта | Проект попадет в решения руководителя |
| Готовность | Расчет стадии проекта | Нельзя корректно определить готовность к гранту |
| Грант / маршрут | Связь проекта с финансированием | Проект попадет в блок “утвердить грантовый маршрут” |
| Срок / дедлайн | Контроль ближайшей даты | Проект попадет в список без срока |
| Следующее действие | Переход от статуса к действию | Руководителю будет непонятно, что делать дальше |
| Риск / комментарий | Управленческие ограничения | Риск может не попасть в повестку |
| Статус | Этап проекта | Проект сложнее отнести к воронке |
| Описание | Суть проекта | Паспорт проекта будет формальным |
| Ссылка на материалы | Быстрый доступ к файлам | НТС не сможет быстро проверить материалы |

В самой панели есть блок `Карта данных`. Он доступен через `Инструменты` -> `Технические блоки`.

## 5. Основные режимы панели

### Рабочий режим

Используется проектной командой. Показывает все рабочие блоки:

- KPI;
- сводка руководителя;
- центр управления;
- проекты;
- гранты;
- качество данных;
- технические блоки при необходимости.

### Режим НТС

Используется для заседания Научно-технического совета. Оставляет только управленческую часть:

- сводку руководителя;
- готовность к НТС;
- решения;
- план на 7 дней;
- матрицу рисков;
- повестку НТС.

### Режим аудита

Используется перед показом. Проверяет:

- загрузку данных;
- подключение модулей;
- качество заполнения;
- готовность интерфейса.

---

## 6. Центр управления

Главный блок панели - `Центр управления`. Он содержит 4 вкладки:

1. `Решения` - что должен решить руководитель.
2. `7 дней` - ближайшие задачи команды.
3. `Риски` - матрица рисков портфеля.
4. `НТС` - повестка и решения к заседанию.

Во вкладках есть счетчики, которые показывают количество элементов без открытия вкладки.

---

## 7. Печать повестки НТС

В меню `Инструменты` доступны команды:

- `Предпросмотр НТС`;
- `Печать НТС`.

Рекомендуемый сценарий:

```text
Предпросмотр НТС -> Проверить состав повестки -> Печать / PDF
```

Печатная версия скрывает технические и рабочие блоки и оставляет только управленческую сводку.

---

## 8. Мобильная версия

На мобильном экране:

- таблица проектов заменяется карточками;
- фильтры сворачиваются в кнопку `Фильтры и поиск`;
- каждый проект можно открыть через кнопку `Открыть паспорт`;
- липкая KPI-панель показывает ключевые показатели при прокрутке.

Проверять мобильную версию нужно на реальном телефоне перед показом.

---

## 9. Если данные не загрузились

В панели есть официальная карточка диагностики `Данные пока не загружены`.

Проверить нужно:

1. Доступ к Google Таблице.
2. Публикацию Apps Script как Web App.
3. Корректность `gid`.
4. Свежесть публикации GitHub Pages.
5. Кеш браузера.

Быстрые действия:

- нажать `Обновить`;
- открыть сайт с параметром версии `?v=final-v1`;
- в блоке `Версия и публикация` нажать `Обновить без кеша`;
- проверить `Settings` -> `Pages` в GitHub.

## 10. GitHub Pages

Для публикации:

1. Открыть репозиторий `STEP3DLab/Technopark_project`.
2. Перейти в `Settings` -> `Pages`.
3. Проверить источник публикации:
   - branch: `main`;
   - folder: `/root`.
4. После коммита подождать 1-5 минут.
5. Открыть сайт в режиме без кеша:

```text
https://step3dlab.github.io/Technopark_project/?v=final-v1
```

Если сайт показывает старый интерфейс, значит GitHub Pages может брать не ту ветку, не тот каталог или браузер показывает кеш.

---

## 11. Apps Script

Apps Script используется для связи сайта с Google Таблицей и отправки пожеланий НТС.

Текущий endpoint указывается в коде сайта и должен быть опубликован как Web App.

При изменении Apps Script нужно:

1. Сохранить проект Apps Script.
2. Создать новую версию развертывания.
3. Проверить доступ `Anyone` / `Anyone with the link`, если сайт должен обращаться публично.
4. Проверить, что endpoint не изменился или обновлен в коде сайта.

## 13. Что нельзя делать без проверки

Не рекомендуется без тестирования:

- переименовывать ключевые колонки Google Sheets;
- менять `gid` листов;
- удалять подключенные JS/CSS-файлы;
- менять endpoint Apps Script;
- убирать `app-ux-v1.js`, потому что он собирает финальную структуру панели;
- менять порядок подключения финальных файлов без проверки.

## 14. Перед показом руководству

Чек-лист:

- сайт открывается по GitHub Pages;
- данные из Google Sheets загружаются;
- KPI не равны нулю, если проекты есть в таблице;
- работает `Режим НТС`;
- работает `Предпросмотр НТС`;
- печать / PDF выглядит чисто;
- мобильная версия не имеет горизонтальной прокрутки;
- технические блоки скрыты по умолчанию;
- кнопка `Добавить пожелание` работает;
- в таблице заполнены ответственные, сроки, гранты и готовность.

## 15. Спринт 3: режим показа проректору

Для финального показа в копии `amAILab/Technopark_project` добавлены безопасные локальные режимы интерфейса. Они не меняют данные и не затрагивают live-репозиторий STEP3DLab.

Рекомендуемая ссылка для демонстрации:

```text
https://amailab.github.io/Technopark_project/?focus&projector&v=sprint3
```

Что включено:

- `Фокус` — скрывает второстепенные рабочие блоки и оставляет управленческую историю показа;
- `Проектор` — увеличивает ключевые метрики, карточки и первый экран для аудитории;
- `Чек-лист` — открывает `docs/DEMO_SCRIPT.md` со сценарием выступления и проверкой перед показом;
- `Alt+F` — быстро включить/выключить фокус-режим;
- `Alt+P` — быстро включить/выключить проекторный вид.

Перед встречей проверить:

1. Первый экран: сводка руководителя и 4 KPI читаются с проектора.
2. Раздел `Главная`: видны 5 решений недели.
3. Раздел `Гранты`: есть маршруты упаковки к 1 июня.
4. Раздел `НТС`: повестка заполнена.
5. Мобильный вид: карточки проектов не дают горизонтальной прокрутки.

Сценарий выступления на 2–3 минуты: [`docs/DEMO_SCRIPT.md`](docs/DEMO_SCRIPT.md).
